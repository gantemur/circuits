## Initial representation versus replacement

Graphical browser initialization may use the accepted headless generator for a
strict native document without geometry. It checkpoints only the initial graphical
representation, never replaces the applied document or creates a saved-project key.
Existing native importer/unsupported behavior remains the fallback. Automatic
synchronization is limited to genuinely clean drafts; portable projects remain
independent and retain their exact saved geometry. Source-free layouts require
explicit ordered selectors or a current-document-owned accepted port configuration.
Names and ground are never used to guess ports.

## Guarded suggestion

Suggest layout operates on the valid current graphical native candidate, not an
obsolete applied copy. Pending text, tools and gestures block suggestion/adoption.
A read-only before/after preview displays family, exact/native and geometry checks,
limitations, Use and Cancel. No rejected drawing can be force-adopted. Language
changes do not invalidate a preview; user interactions, even edit-and-restore, do.
Authorization captures applied identity/revision/serialization, draft identity,
scientific/geometry revisions, exact graph/native content, pending/control/gesture
state, monotone generation and ordered ports. Recheck synchronously before Use.
Project read/confirmation ownership and layout consent cannot authorize each other.

Adoption independently validates exact old/new native equality and project validity,
then records a single bounded geometry-only history operation. Undo/Redo restore
stored graph representations including allocation counters and anchors. Scientific
revision, applied identity and Form/JSON remain unchanged. Replaced-handle selections
and gestures retire. Saved-content comparisons remain independent of Apply/history.
