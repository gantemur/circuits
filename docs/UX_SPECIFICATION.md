# UX workspaces: implemented scope

Status: reviewed implementation `01bd698` was fast-forwarded to `main` and published at [https://gantemur.github.io/circuits/](https://gantemur.github.io/circuits/) on 11 October 2026. The [validation](https://github.com/gantemur/circuits/actions/runs/38116427472) and [Pages deployment](https://github.com/gantemur/circuits/actions/runs/38116427451) succeeded, and the live three-file package matched the local build byte for byte. This redesign supersedes the earlier Phase 2B interface layout plan without importing unreviewed reduction mathematics.

## Working model

The working page has a compact brand/language header, a shared circuit bar, and **Analyze** and **Transform** workspaces. About contains the introduction. A single validated native v1 document supplies circuit topology, component values, sources, observations, and initial conditions to both workspaces. The selector identifies a preset, modified preset, or custom circuit; the bar also offers Edit circuit, New, Import JSON, Export JSON, and Reset example when applicable. The URL remains a static `/circuits/` page with relative assets; workspace switching is in memory and does not change the URL or document. Synthesize is a future workspace, with no empty tab today.

Analyze places one verified schematic or actual topology table above the panels. The compact inspector lets a selected component expose value/gain, ordered terminals, kernel terminal law, and a route to highlighted equation contributions. Its Sources & initial conditions disclosure edits shared DC values, RMS AC phasors, time waveforms, and storage initialization; peak sinusoid amplitude remains distinct from RMS. Source and initial definitions remain in the native experiment. The circuit editor is a separate screen with Form and JSON views and an explicit return. Its existing strict parsing, Apply, Discard/Restore, stale-base conflicts, ground-by-ID checks, reference protection, and node-pending behavior remain. Form and JSON drafts stay separate across view and language changes. New creates only an empty form draft until Apply.

## Panel model and calculations

Analyze starts with two panels and allows zero through three, with an explicit Add action in the zero state and an explained disabled Add at the limit. Every panel has a stable ID, type selector, collapse, remove, move up/down, and full-width controls. Settings are collapsed initially and live beside their result. The supported types are DC solution, frequency response, transient response, equations and contributions, and compact DC port characteristics. Duplicate types have separate inputs, outputs, frequencies/ranges, durations/steps, or port/load selections. Frequency exposes a unit-input numerical sweep, configured physical RMS AC result, and restricted algebraic extraction as distinct outputs. Port characteristics offers Open comparison with its valid port/load selection.

A typed browser-only workspace state stores view, editor view, panel IDs, settings, and pending text/errors. It is never exported in native JSON and is not persisted across sessions. On invalid panel text, the last valid setting and result remain visible with a translated warning; other panels continue. Pending text/error follows panel ID across reordering, expansion, navigation, and language switching. Topology changes preserve available selections and flag missing source/output/terminal references for explicit reselection. Panel CSV uses that panel's validated result and configuration. Computation is per visible, uncollapsed panel; identical settings share cached results keyed by document identity/revision and relevant panel settings. DC and equation inspection need no transfer input, and transient validation cannot block frequency or DC. Hidden or removed panels do not run repeated simulations.

The initial divider layout is DC plus DC port. RC/RL/RLC examples suggest frequency plus transient; the amplifier suggests DC plus frequency. Selecting another preset changes to its suggestion only while the current layout is still the untouched suggestion and has no pending panel text. Otherwise it preserves the layout and drafts. Restore suggested layout explicitly replaces panel configuration and pending panel text, while leaving the editor drafts and validated circuit alone. Validated component/source edits do not reset layout. Cross-session workspace persistence is outside scope.

## Transform and mathematical boundary

This section describes the released UX baseline. The subsequent task-branch [Phase 2B specification](PHASE_2B_SPECIFICATION.md) extends Transform with passive resistor methods beside the DC comparison.

Transform currently offers only **Thévenin/Norton — DC**. It retains the Phase 2A terminal orientation, source suppression, controlled-source retention, solved original/Thévenin/Norton load comparison, short-circuit cross-check, diagnostics, and explicit unsupported/degenerate outcomes. The original network is shown once, beside one selected equivalent representation on desktop. On mobile, Original/Equivalent controls switch the drawing; comparison values remain accessible. Source-suppressed and loaded constructions are temporary experiments, not edits to the original. The tool preserves the chosen DC port relation and positive-resistance load comparison, not internal states or frequency/transient behavior. There is no Save equivalent action because conversion to a native document is not implemented here.

An explicit Analyze → Transform handoff carries ordered p/q terminals and load even before Transform has opened. Valid Transform choices survive circuit and workspace changes; if a selected node disappears, that terminal is marked for reselection instead of silently choosing a different node. Unapplied load text survives ordinary navigation. The mobile drawing switch does not hide numerical metrics, comparison tables, diagnostics, or unsupported/failure outcomes. Tables scroll within the result container.

Port count describes an external view, not an immutable circuit category. One-port, two-port, and retained-terminal descriptions can share the same circuit model; general terminal behavior is the foundation for Kron reduction. A transfer function for one source/load experiment is not generally a complete equivalence invariant. Mathematical validity is distinct from implemented support. General boundary selectors and two-port/reduction operations wait for a supported mathematical milestone. No new reductions, impedance sweeps, synthesis, device models, graphical wiring, or unrestricted symbolic extraction are part of this branch.

## Mobile and evidence

At 320 and 390 CSS px, the circuit bar wraps, panel grid has one column, settings remain collapsed, and schematic, matrices, and comparison tables scroll within their containers rather than widening the page. Panel full width enlarges plots where available. The plot SVG axis and grid paths explicitly have no fill; failed samples break line paths, zero magnitude retains undefined phase, and units/logarithmic frequency labels remain. Controls use labels, keyboard-operable buttons, visible focus, translated names/errors in English and Mongolian, and `hidden` for inactive views. Scientific IDs, numerical values, SI units, JSON keys, and CSV headers remain language-independent.

Verification includes the existing kernel acceptance suite; new focused state tests cover duplicate panels, independent settings and CSV, stable IDs/pending errors, isolated invalid settings, missing-reference reconciliation, and unfilled/gapped plots. The task requires clean install, complete tests, typecheck, kernel and site builds, `git diff --check`, and actual-browser checks in both languages at desktop, 390 px, and 320 px. Report any unavailable browser download interaction separately from serialization tests.

Panel type changes recalculate reference requirements for the new type: DC has no transfer-input/output requirement; frequency, transient, and port panels identify their own missing selections. JSON-editor and file-import diagnostics retain identifiers and parameters so visible errors retranslate when the language changes, while rejected drafts and the last valid circuit remain intact.

The next milestone is a separately specified, mathematically supported transformation or other scientific capability using this shared editor and Transform workspace; it must not create a second unrelated circuit-design interface.
