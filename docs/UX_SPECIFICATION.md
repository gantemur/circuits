# UX workspaces: implemented scope

Status: reviewed implementation `01bd698` was fast-forwarded to `main` and published at [https://gantemur.github.io/circuits/](https://gantemur.github.io/circuits/) on 11 October 2026. The [validation](https://github.com/gantemur/circuits/actions/runs/38116427472) and [Pages deployment](https://github.com/gantemur/circuits/actions/runs/38116427451) succeeded, and the live three-file package matched the local build byte for byte. This redesign supersedes the earlier Phase 2B interface layout plan without importing unreviewed reduction mathematics.

## Working model

The working page has a compact brand/language header, a shared circuit bar, and **Analyze** and **Transform** workspaces. About contains the introduction. A single validated native v1 document supplies circuit topology, component values, sources, observations, and initial conditions to both workspaces. The selector identifies a preset, modified preset, or custom circuit; the bar also offers Edit circuit, New, Import JSON, Export JSON, and Reset example when applicable. The URL remains a static `/circuits/` page with relative assets; workspace switching is in memory and does not change the URL or document. Synthesize is a future workspace, with no empty tab today.

Analyze places one verified schematic or actual topology table above the panels. The compact inspector lets a selected component expose value/gain, ordered terminals, kernel terminal law, and a route to highlighted equation contributions. Its Sources & initial conditions disclosure edits shared DC values, RMS AC phasors, time waveforms, and storage initialization; peak sinusoid amplitude remains distinct from RMS. Source and initial definitions remain in the native experiment. The circuit editor is a separate screen with Form and JSON views and an explicit return. Its existing strict parsing, Apply, Discard/Restore, stale-base conflicts, ground-by-ID checks, reference protection, and node-pending behavior remain. Form and JSON drafts stay separate across view and language changes. New creates only an empty form draft until Apply.

## Panel model and calculations

Analyze starts with two panels and allows zero through three, with an explicit Add action in the zero state and an explained disabled Add at the limit. Every panel has a stable ID, type selector, collapse, remove, move up/down, and full-width controls. Settings are collapsed initially and live beside their result. The released types are DC solution, frequency response, transient response, equations and contributions, compact DC port characteristics, and Phase 2C **Port analysis — frequency** for one/two-port Z/Y experiments and loading. Duplicate panels keep independent settings. Frequency exposes a unit-input numerical sweep, configured physical RMS AC result, and restricted algebraic extraction as distinct outputs. DC port characteristics still offers Open comparison with its valid port/load selection.

A typed browser-only workspace state stores view, editor view, panel IDs, settings, and pending text/errors. It is never exported in native JSON and is not persisted across sessions. On invalid panel text, the last valid setting and result remain visible with a translated warning; other panels continue. Pending text/error follows panel ID across reordering, expansion, navigation, and language switching. Topology changes preserve available selections and flag missing source/output/terminal references for explicit reselection. Panel CSV uses that panel's validated result and configuration. Computation is per visible, uncollapsed panel; identical settings share cached results keyed by document identity/revision and relevant panel settings. DC and equation inspection need no transfer input, and transient validation cannot block frequency or DC. Hidden or removed panels do not run repeated simulations.

The initial divider layout is DC plus DC port. RC/RL/RLC examples suggest frequency plus transient; the amplifier suggests DC plus frequency. Selecting another preset changes to its suggestion only while the current layout is still the untouched suggestion and has no pending panel text. Otherwise it preserves the layout and drafts. Restore suggested layout explicitly replaces panel configuration and pending panel text, while leaving the editor drafts and validated circuit alone. Validated component/source edits do not reset layout. Cross-session workspace persistence is outside scope.

## Transform and mathematical boundary

The following DC comparison description records the original UX-workspaces release baseline. The later [Phase 2B specification](PHASE_2B_SPECIFICATION.md) adds passive resistor methods beside it; [Phase 2D1](PHASE_2D1_SPECIFICATION.md) adds their guided preview/use workflow.

The baseline Transform offered **Thévenin/Norton — DC**. It retains the Phase 2A terminal orientation, source suppression, controlled-source retention, solved original/Thévenin/Norton load comparison, short-circuit cross-check, diagnostics, and explicit unsupported/degenerate outcomes. The original network is shown once, beside one selected equivalent representation on desktop. On mobile, Original/Equivalent controls switch the drawing; comparison values remain accessible. Source-suppressed and loaded constructions are temporary experiments, not edits to the original. The DC method preserves the chosen port relation and positive-resistance load comparison, not internal states or frequency/transient behavior. It has no Save equivalent action.

An explicit Analyze → Transform handoff carries ordered p/q terminals and load even before Transform has opened. Valid Transform choices survive circuit and workspace changes; if a selected node disappears, that terminal is marked for reselection instead of silently choosing a different node. Unapplied load text survives ordinary navigation. The mobile drawing switch does not hide numerical metrics, comparison tables, diagnostics, or unsupported/failure outcomes. Tables scroll within the result container.

Port count describes an external view, not an immutable circuit category. One-port, two-port, and retained-terminal descriptions can share the same circuit model; general terminal behavior is the foundation for Kron reduction. A transfer function for one source/load experiment is not generally a complete equivalence invariant. Mathematical validity is distinct from implemented support. Phase 2C adds bounded exact-ID one/two-port selectors, impedance/admittance sampling, and two-port loading in Analyze; it does not add a new Transform reduction, synthesis, device models, graphical wiring, or unrestricted symbolic extraction.

## Mobile and evidence

At 320 and 390 CSS px, the circuit bar wraps, panel grid has one column, settings remain collapsed, and schematic, matrices, and comparison tables scroll within their containers rather than widening the page. Panel full width enlarges plots where available. The plot SVG axis and grid paths explicitly have no fill; failed samples break line paths, zero magnitude retains undefined phase, and units/logarithmic frequency labels remain. Controls use labels, keyboard-operable buttons, visible focus, translated names/errors in English and Mongolian, and `hidden` for inactive views. Scientific IDs, numerical values, SI units, JSON keys, and CSV headers remain language-independent.

Verification includes the existing kernel acceptance suite; new focused state tests cover duplicate panels, independent settings and CSV, stable IDs/pending errors, isolated invalid settings, missing-reference reconciliation, and unfilled/gapped plots. The task requires clean install, complete tests, typecheck, kernel and site builds, `git diff --check`, and actual-browser checks in both languages at desktop, 390 px, and 320 px. Report any unavailable browser download interaction separately from serialization tests.

Panel type changes recalculate reference requirements for the new type: DC has no transfer-input/output requirement; frequency, transient, and port panels identify their own missing selections. JSON-editor and file-import diagnostics retain identifiers and parameters so visible errors retranslate when the language changes, while rejected drafts and the last valid circuit remain intact.

At the original UX-workspaces release, the next milestone was a separately specified transformation using this shared editor and Transform workspace. Phase 2B and Phase 2D1 subsequently implemented passive-resistor methods and their guided visual workflow without a second circuit-design interface.

## Phase 2D1 visual-learning extension

The published [Phase 2D1 specification](PHASE_2D1_SPECIFICATION.md) extends this workspace baseline. In resistor Transform, ordered retained terminals and a concrete operation/operand selection precede an explicit **Preview transformation**. Changing settings or the validated circuit invalidates the preview for application. Successful previews lead with the selected identity, a declared boundary-voltage/current experiment, and full-network before/after node-edge drawings where reliable. Removed and generated edges use line styles and labels as well as color. A separate local rewrite is labeled as a subset; large or geometrically ambiguous custom networks use exact tables instead of a misleading compact drawing. Matrices, physical check differences/limits, and strict JSON are expandable. Unsupported source/storage networks identify blockers and offer explicit suitable examples. The DC one-port method remains separate and has no apply action.

**Use transformed circuit** rechecks the current candidate and revision, then goes through the existing validated native-document change path. **Return to original circuit** restores a session snapshot only while the applied transformed document remains current. Either change asks for explicit confirmation when Form or JSON has an unapplied draft; the draft is retained and later marked conflicted. Ordinary navigation preserves Transform selections and pending editor text. Explicitly opening a suggested resistor example starts that new lesson with its observed terminals; ordinary preset changes continue to show missing old terminals for reselection.

All 14 presets now have topology-matched, parameter-aware SVG drawings, keyboard-selectable components, exact IDs, and expandable topology tables. A nonmatching custom circuit keeps the table fallback. A shared collapsible study guide follows the selected example in Analyze and Transform, preserving its open state and panel settings across navigation/language switching. Its action focuses a suitable existing panel, adds within the three-panel limit, or asks the student to choose a panel for replacement. Four app-level scalar references are explicitly baseline targets; edited circuits use fresh kernel results rather than those coefficients. The native v1 schema and scientific algorithms are unchanged.

## Phase 2D2 task-branch extension

[Phase 2D2](PHASE_2D2_SPECIFICATION.md) adds eight native examples and brings the task branch to 22 presets without changing this workspace model or the published Phase 2D1 baseline. Filter presets suggest frequency and transient panels with bounded lesson-specific ranges. Source-free impedance ladders suggest a one-port `(in,0)` Z sweep rather than an unforced transfer panel. These suggestions are installed only for a fresh suggested layout or an explicit Restore action; independent edited panels and pending invalid values remain as configured. The RLC drawing marks the voltage observation chosen in a panel, while each panel keeps its own output choice. Curated whole-circuit drawings require an exact topology match and retain value edits; a different topology uses the exact table fallback. The shared guide and fixed authored references remain outside native JSON.

## Phase 3A2 task-branch extension

[Phase 3A2](PHASE_3A2_SPECIFICATION.md) retains the same workspace and three-panel limit while accepting strict v1 or v2 native documents through version routing. Four diode presets suggest DC plus characteristic, DC plus source sweep, or DC plus incremental frequency panels. Student-configured panel types, IDs, pending text, and source/output selections survive ordinary navigation and example changes; missing references require explicit reselection. Form and inspector edits validate diode model parameters before changing the applied document. A failed nonlinear bias is displayed without reverting a valid v2 document. Characteristic ranges belong to their panels; fitting to Q is an explicit action. A DC sweep starts only on Run, yields and may be cancelled, keeps failed samples as gaps, and cannot export stale data. V2 transient, port, and Transform panels state their unsupported status while retaining settings. The four new drawings require exact topology matching; custom circuits use the exact table. All new labels and failures are bilingual at render time, including at mobile widths. This branch does not change the published Phase 2D2 site until release.

## Phase 3A4 task-branch extension

[Phase 3A4](PHASE_3A4_SPECIFICATION.md) enables strict-v2 nonlinear time analysis in the existing Transient panel, without changing v1 rendering or the three-panel limit. It does not solve on render: Run snapshots the applied native document and accepted output/duration/step, then starts one bundled Web Worker. Cancel terminates it. Scientific changes, invalid pending transient text, missing output, panel type/removal/collapse/replacement, Analyze departure, and page hiding permanently retire active and completed runs. Language switches, panel ordering and width do not. Other panels keep independent settings/results; a second v2 run waits for the active one without a queue. Accepted left/right event samples share timestamps; only valid prefix samples appear after a kernel failure. The selected-sample disclosure keeps detailed A/V/W/J diagnostics separate from the DC Q inspector. Four guided, topology-verified browser copies bring the task branch to 30 presets; the released site remains Phase 3A2 until integration. V2 port analysis and Transform stay unsupported.


## Phase 3B2 task-branch extension

Strict v3 adds five BJT presets (35 total) without changing the released three-panel workspace. The DC panel and Q inspector expose entering c/b/e currents, voltage differences, transport terms, signed absorbed power, descriptive regions and labeled local derivatives. Equations explains the continuous laws and nodal/tangent stages; it does not claim a native-v1 equivalent or pole extraction. Frequency retains independently configured source/output/grids, unit transfer, physical RMS AC and gaps for failed samples. Bounds are 64 unknowns, 128 components and the existing 241 sweep points.

Positive finite Q model parameters and shared sources/resistors edit only through strict validation. Invalid pending inspector text remains correctable across translation and other scalar edits. Native input+blur is handled as well as change. Five topology-verified drawings use conventional emitter arrows, while all reported currents retain the entering convention; narrow diagrams scroll locally with readable labels. Custom circuits use exact three-terminal topology tables. Form construction is deferred for applied v3, with its existing draft retained and protected from Apply; JSON supports arbitrary strict v3. Unsupported nonlinear ports, Transform, BJT transients and source/characteristic sweeps report a translated message even if their old selections are missing. Existing v2 worker transients remain available. This is not a deployment record.
